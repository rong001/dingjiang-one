# 鼎匠 ONE · 企业经营中枢

面向跨境品牌企业的 ToB 经营工作台，将全渠道订单、供应链、制造、财务和治理串成可操作的业务链路。项目依据深圳鼎匠创新科技招聘 JD 与 TOPDON 公开资料独立设计，用于方案讲解和交互评审，不是该企业的官方系统。

## 使用

直接打开 [鼎匠 ONE 在线工作空间](https://rong001.github.io/dingjiang-one/)，或在本地用任意静态 HTTP 服务托管 `dist/`。例如已安装 Python 时，在仓库目录运行：

```sh
python -m http.server 8080 --directory dist
```

随后打开 `http://localhost:8080`。站点无需数据库、API 密钥或前端构建。直接打开 `dist/index.html` 也可浏览；稳定的浏览器存储和文件行为建议通过 HTTP/HTTPS 使用。

在工作空间中切换业务场景和界面风格。场景互相独立，切换后可继续先前的处理记录；界面风格与信息密度只改变展示方式。

## 三套完整业务数据

数据日期锚定 **2026-09-27**。每套均包含 24 笔订单、6 笔采购、6 张工单、12 个客户账户、4 家供应商，以及可追溯的库存流水和审计记录。

| 场景 | 关注点 | 初始已入账凭证 |
| --- | --- | ---: |
| 稳健经营 `global` | 全球渠道、库存水位、履约与贡献利润 | 6 |
| 渠道拓展 `growth` | 经销商订单、采购备货、制造与交付产能 | 4 |
| 月结冲刺 `closing` | 结算差异、会计凭证、控制复核与关账 | 8 |

三套界面为 **靛蓝 `indigo`、石墨 `graphite`、深海 `midnight`**，并提供舒适 / 紧凑信息密度。全部场景均可使用任意界面，业务能力和数据完整性一致。

## 业务链路

- **订单到凭证**：新建订单 → 审核 → 校验库存并发货 → 结算差异归因 → 生成平衡凭证 → 查看业务与审计记录。
- **需求到库存**：订单需求 / 库存预警 → 采购申请 → 审批 → 收货入库 → 履约交付；预置采购和工单可通过 `sourceOrder` 关联来源订单。
- **研发到交付**：产品与 BOM 基线 → 生产工单 → 下达 → 报工 → 质检入库 → 批次追溯。
- **运营到治理**：主数据问题 → 标准映射 → 集成状态 → 控制复核 → 审计证据；配合项目预算、资产和区域基础设施视图。

功能按经营、渠道、供应链、研发制造、财务、治理和平台管理组织。业务模块支持筛选、详情和动作入口，主题选择贯穿整个工作空间。

## 数据与实现边界

**这是完整交互前端，使用合成业务样本；不是企业生产后端。** 产品名称参考公开资料，价格、库存、客户、供应商、人员、仓库、预算、风险和凭证均为独立设计的数据，不代表公司实际经营情况。

状态保存在当前浏览器的 `localStorage`，按场景隔离；不同设备、浏览器和域名不共享数据。清理站点数据会移除本地操作记录。场景恢复仅作用于当前场景；旧版存储不会被新场景模块删除。

本项目没有连接企业 ERP、WMS、MES、PLM、银行或广告平台。角色切换、审计、恢复、集成和营销同意功能用于表达业务规则，不提供服务端身份认证、不可篡改审计、实际备份恢复或法规认证。GitHub Pages 只托管静态文件。

财务采用不含税人民币、固定 SKU 标准成本以及既定平台费用和履约费用。税务、汇兑、退款、信用账期、应收应付子账和法定报表需在生产实施中补齐。JD 中的 IPO 要求是设计输入，不代表已核实公司的上市进度。

## 技术

原生 HTML / CSS / JavaScript、hash 路由、浏览器本地存储；图表与图标资源随 `dist/vendor/` 一并托管。无需运行时 CDN。以现代桌面浏览器为主要使用环境，提供窄屏布局、键盘焦点、原生表单与低动态偏好支持。
